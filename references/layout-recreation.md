# 轻改二创 spec 手册（relayout_light.py）

## 零、改动边界（写 spec 前先对照）

轻量二创，不是重新设计。允许改的 9 类 → 对应 spec 字段：

| 可改 | spec 落点 |
|---|---|
| 配色方案 | `tint` |
| 模块顺序 | `blocks` 顺序（移 2–3 块） |
| 局部布局 | `cols` / `row_h` / `widths` / 块内元素换位 |
| 标题层级优化 | 同层级内的断行、行长；**不改字号档位** |
| 文案轻微改写 | 同义替换、删冗余词；数字时间条件零改动 |
| 强调框/编号/分割线/图标 | `quote` / `num` / `rule` / `chip` |
| 图片裁切微调 | 只调比例，不换主体 |
| 样式微调 | 圆角、描边、行距小步调 |
| 小红书尺寸 | `size` 固定 1080×1440 |

禁止：改主题、加无关内容、删关键信息、换视觉体系、改成海报/长图/强封面、打散信息结构、夸张视觉改造。

> 拿不准时用默认值：`skin` 抄原骨架、`tile: gray`、字号档位不动，只换 `tint` + 挪 2 块顺序 —— 这就是最安全的一版。

## 一、spec 全字段

```json
{
  "skin": "report",
  "tint": "tea",
  "num": "circle",
  "tile": "gray",
  "zebra": true,
  "rule": true,
  "renumber": true,
  "size": {"width": 1080, "height": 1440},
  "header": { ... },
  "blocks": [ ... ],
  "footer": {"source": "依据：……", "brand": "中公教育"}
}
```

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `skin` | ✅ | `report` / `sheet` | 决定整套骨架，选错就是大改 |
| `tint` | ✅ | tea / pine / inkblue / brick / slate | 主色，五者明度一致 |
| `num` | ❌ | circle / ring / square / bar | 序号形态，默认 circle |
| `tile` | ❌ | tint / gray / line | 卡片底，默认 tint |
| `zebra` | ❌ | true / false | 表格斑马纹，默认开 |
| `rule` | ❌ | true / false | 模块分割线，默认开 |
| `renumber` | ❌ | true / false | 按位置自动编号，默认开 |
| `size` | ❌ | 1080×1440 | 固定输出，不用改 |

## 二、header

| 字段 | 说明 |
|---|---|
| `kicker` | 顶部小字。`report` 在右上，`sheet` 在 logo 右侧 |
| `short` | 续页顶部的小标题（第 2 页起显示） |
| `title_lines` | 主标题，数组每项一行，**手动断行** |
| `title_size` | 主标题字号，`report` 默认 64，`sheet` 默认 56。中文标题 1 行约放 9 字 |
| `corner` | 右上角块 `{"v":"120","l":"13 个岗位"}`；`sheet` 里是白底块，宽度自适应，文字控制在 10 字内 |
| `sub` | 副标题一行，超过 40 字会折行 |
| `metrics` | `report` 专用，2–4 个 `{"v":"13","l":"岗位"}`。`l` 不要太长，超过卡片宽度会折行并把整条撑高 |

## 三、blocks

`blocks` 数组顺序就是最终渲染顺序，改顺序即重排。`no` 不用写。

### bars 条形对比

```json
{"type":"bars","title":"名额去哪儿了","chip":"广州 59 人 49.2%",
 "lead":"一句说明，1 行","items":[{"label":"广州","value":"59 人 49.2%","pct":49.2}]}
```

- `pct` 只用于条长比例，必须与 `value` 里的数字一致
- `label` 控制在 8 字内，超了会自动缩字号
- 条数 ≤ 7 条，再多就换 `table`

### tiles 卡片网格

```json
{"type":"tiles","title":"非工科的出口","chip":"19 人","lead":"……",
 "cols":3,"row_h":84,
 "items":[{"h":"电子信息/计算机","sub":"3 个岗位","m":"12 人"}],
 "note":"卡下补一行说明"}
```

- `cols`：2 / 3 / 4。名称长就用 2 列，短名用 3 列
- `m`：右上角数字；`sub`：副行，自动折行最多 2 行
- 卡高自动取最长的一条，`row_h` 只设下限

**长明细用 `lines`（不限行数）**：原素材卡片里有 3–4 行小字时，`sub` 放不下会被截断（丢信息），改用 `lines`：

```json
{"h":"广州：拆开招","m":"3 个机电岗","head":false,
 "lines":["按方向分设","岗1 只要机械（5 个本科专业）","岗2 只要自动化与机器人（4 个）"]}
```

- `head: true`：第 1 行作加粗小标题，其余灰色小字（对应「100% / 本科及以上 / 说明」这类卡）
- 不写 `head`：全部灰色小字
- `sub` 想控制断行就写 `\n`，避免末行只剩「位）」这类孤字

### table 表格

```json
{"type":"table","title":"报考条件","cols":["事项","说明"],
 "widths":[0.2,0.8],"row_h":46,
 "groups":["报考条件","报考条件","注意事项"],
 "rows":[["学历学位","本科及以上"]]}
```

- `groups` 与 `rows` 一一对应，连续相同的 group 合并成左侧竖排栏（`sheet` 骨架的标志）
- `widths` 是列宽比例，和等于 1
- `zebra` 斑马纹会让长表更好读
- 超页自动拆成「（续）」

### steps 横排流程

```json
{"type":"steps","items":[{"no":"1","h":"报名","sub":"10.21—10.30"}]}
```

最多 6 个，再多会挤。

### quote 结论块

```json
{"type":"quote","label":"一句话结论","text":"……","dark":true}
```

`dark: true` 深色块（原版常见），`false` 浅色块。放数组末尾。

### section 要点列表

```json
{"type":"section","title":"编码规则","items":["一行一条"]}
```

### notice 提示条

```json
{"type":"notice","text":"一句话提醒"}
```

浅色圆角条，适合放报名截止这类提示。

## 四、布局与页数

- 固定 1080×1440，边距 64，块间距 22，页脚 76
- 分页：整块放不下就换页，**不缩小、不放大**；单块超过整页才拆（表格按行拆、列表按条拆）
- 页数由内容决定。一页纸素材通常 2 页；内容特别密才 3 页

### 想压页数（按性价比排序）

1. 把相邻的小要点合并进上一块的 `note`（省 40–60px）
2. `row_h` 减 6–10（每行省 6–10px）
3. `lead` 压到一行（省 30px）
4. 合并同组模块（如把「注意事项」并进主表）

### 想加页数 / 填空白

1. `row_h` 加 6–10
2. 把某块拆成两块独立模块
3. 不要加大字号，会破坏与原版的字号层级关系

## 五、常见问题

| 现象 | 原因 | 改法 |
|---|---|---|
| 指标卡标签溢出到隔壁 | `metrics[].l` 太长 | 压到 6 字内 |
| 条形图标签压到条上 | `label` 太长 | 改短，或用「A/B」缩写 |
| 竖排分组字叠在一起 | 组内行太少，装不下 4 个字 | 脚本已按区域高度缩字号；仍挤就把该组并到上一组 |
| 表格末行贴着页脚线 | 该页塞得刚好 | `row_h` 减 4，让最后一行掉到下一页 |
| 第 2 页大半空白 | 内容只有 1.5 页 | 正常，末页留白；也可把结论块放末页压住底部 |
| 出来的图看着像换了个作者 | `skin` 选错或 `tile` 从 gray 改成 tint | 回到原素材的骨架和卡片底 |
| 续页标题显示「接上页（续）」 | 表格没写 `title` | 给表格加 `title` |
