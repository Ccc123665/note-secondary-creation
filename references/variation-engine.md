# 变量引擎（Variation Engine）

本文件说明「为什么每次不一样」以及「怎么保证不一样但不失控」。具体写法见 `copy-patterns.md`，视觉参数见 `visual-system.md`。

## 一、设计原则

1. **固定层只增不减**：事实、合规、logo、长度是常量，采样永远碰不到。
2. **变量层只动表达**：视角、结构、配色、版式、插画可以全换，事实口径不变。
3. **组合优于单维**：单换颜色只是换皮，真正降低同质化的是「视角 × 结构 × 钩子」三件套同时变。
4. **可复现**：seed → variant 一一对应，线上效果好的版本能精确复刻。
5. **可去重**：每次落盘指纹，下一次采样主动避开，不靠 AI 记性。

## 二、11 个维度

### 内容维度（决定"读起来不同"，权重最高）

| 维度 | 取值 | 差异化强度 |
|---|---|---|
| `perspective` | 备考者自述 / 过来人复盘 / 数据观察者 / 老师答疑 / 清单罗列 / 场景对话 | ★★★★★ |
| `hook` | 反常识 / 数字冲击 / 痛点共鸣 / 时间紧迫 / 结论前置 / 提问 / 对比 | ★★★★☆ |
| `structure` | 总分总 / 时间线 / 问题-解答 / 清单体 / 对比拆解 / 步骤流 | ★★★★★ |
| `tone` | 姐妹口语 / 冷静分析 / 干货直给 / 温和陪伴 / 犀利提醒 | ★★★★☆ |
| `rhythm` | 短句密排 / 长段+小标题 / 编号列表 / 引号对话 | ★★★☆☆ |
| `title_pattern` | 数字型 / 疑问型 / 对比型 / 结论型 / 身份型 / 紧迫型 | ★★★☆☆ |

### 视觉维度（决定"看起来不同"）

| 维度 | 取值 | 差异化强度 |
|---|---|---|
| `palette` | 12 套（cream_orange / mist_blue / mint / paper_pink / kraft / sky / forest / lilac / ink_red / navy_gold / black_lime / wine） | ★★★★★ |
| `layout` | 杂志刊头 / 卡片流 / 大字报 / 手账便签 / 数据页 / 目录索引 | ★★★★★ |
| `cover` | 数字卡 / 关键词大字 / 问题句 / 目录预告 | ★★★★☆ |
| `font_pair` | 5 组（缺失自动回退） | ★★☆☆☆ |
| `deer` | study / cheer / sprint / harvest / board / rest | ★★★☆☆ |

## 三、采样算法

```
输入：history（最近 20 条指纹）、seed、--set 覆盖
1. rng = random.Random(seed)
2. 对每个维度：
     base_weight = 1.0
     for i, rec in enumerate(history[:12]):
         if rec[key] == v:
             base_weight *= 0.35 if i < 3 else 0.72    # 越近衰减越狠
     weight = max(base_weight, 0.02)
     按权重抽一个值
3. 约束校验：
     a) 与最近 3 条任一条「重合维度数」≤ 2
     b) (structure, layout, palette) 三元组不在最近 10 条出现
     c) n>1 时，本批次内部同样满足 a)
   不满足 → 重抽，最多 200 次
4. 200 次仍失败 → 放宽为「仅校验 a」，variant.json 标 relaxed: true
```

**为什么是 0.35 / 0.72**：最近 3 条用过的值直接砍到三分之一概率，能有效避免"连着两次撞衫"；4-12 条只做温和抑制，保留长期多样性。

## 四、批量出多版本（`--n 3`）

同一素材要 3 个版本时，不是跑 3 次脚本（可能撞），而是**一次采样 3 份互斥组合**：

- 三份之间 `perspective`、`structure`、`palette` 必须两两不同
- 三份之间颜色模式（light/dark）至少 2 种
- 输出 `variant_v1.json` / `variant_v2.json` / `variant_v3.json`

这样三篇发在矩阵号上，视觉和叙事都不会撞。

## 五、多样性自检（人工兜底）

同一素材连续出 3 版后，对照检查：

| 检查项 | 合格线 |
|---|---|
| 标题主推 | 3 条句式不同、首词不同 |
| 开头两句 | 不能有相同句式（如都用"很多同学问我"） |
| 段落骨架 | 小标题数量/顺序不同 |
| 配色 | 3 版主色不同 |
| 封面 | 信息组织方式不同（数字卡 vs 大字 vs 目录） |
| 插画 | 小鹿姿态不同 |

任一不合格 → 用 `--set` 定向改该维度重出。

## 六、定向覆盖（用户指定风格时）

```bash
# 指定语气 + 配色，其余仍随机
--set tone=冷静分析 --set palette=navy_gold
```

- `--set` 的维度不参与采样，直接采用
- 但**仍参与去重校验**：如果用户指定的组合刚用过，脚本会提示"该组合 1 小时前用过"，建议换配色
- 可用 `--force` 忽略提示

## 七、指纹与历史

每次交付后 `--commit` 写入 `history/fingerprints.jsonl`：

```json
{"ts": "2026-10-20T10:12:33", "seed": 1734567890, "source": "2027国考选岗攻略", "out": "output/.../v1_abc123",
 "dimensions": {"perspective": "数据观察者", "structure": "对比拆解", "palette": "navy_gold", "...": "..."}}
```

用途：
1. 下次采样去重
2. 复盘"哪套组合数据好"（可手工加 `metrics` 字段）
3. 避免同一素材在同一账号重复发相似内容

历史文件超过 500 条时，脚本自动只保留最近 500 条（防止无限增长）。
