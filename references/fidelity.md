# 信息保真规则

**一句话**：可以换 100 种说法，不能动 1 个数字。

同质化是"表达重复"，不是"事实重写"。所有差异化都发生在措辞层，事实层是冻结的。

---

## 一、事实卡字段

```json
{
  "id": "F03",
  "type": "date",
  "level": "must",
  "statement": "报名时间：2026 年 7 月 22 日 9:00 至 7 月 28 日 17:00",
  "source": "第 1 页「报名时间」",
  "numbers": ["2026", "7", "22", "9", "28", "17"],
  "note": "起止时间都要写，不能只写截止"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | F01 起顺序编号，正文用 `[[F01]]` 引用 |
| `type` | ✅ | number / date / rule / name / conclusion / advice |
| `level` | ✅ | must（必须覆盖）/ should（覆盖 ≥60%） |
| `statement` | ✅ | 事实原句，尽量贴原文，不改写 |
| `source` | ✅ | 页码 / 章节 / 图片编号，便于回查 |
| `numbers` | 条件 | 含数字时为必填，用于防篡改比对 |
| `note` | ❌ | 边界说明（如"仅为预估值""官方只公布前三天"） |

## 二、must / should 判定

### 一律 must（删了笔记就不成立）

| 类型 | 例子 |
|---|---|
| 招录规模 | 招 11779 人、9344 个职位 |
| 时间节点 | 报名起止、笔试日期、准考证打印时间 |
| 资格门槛 | 学历、专业、年龄、基层经历、应届/往届 |
| 核心规则 | "只能报一个岗位""资格审查贯穿全程" |
| 关键结论 | "深圳竞争比全省第一" |
| 数据口径 | "截至报名第三天 18 时"（不说清就是失真） |

### 可为 should（细节与补充）

- 举例、背景解释、历史对比
- 流程中的操作细节（如"照片要求蓝底"）
- 建议类内容（"可以先筛专业"）
- 单一岗位的次要要求

### 判断口诀

> 读者拿这条笔记去报名，**少了这条会不会报错？** 会 → must。

## 三、抽取四步法

1. **先搭骨架**：这份素材讲的是"什么事 + 几个关键数字 + 哪几个时间 + 什么条件"
2. **再扫数字**：全文所有数字/百分比/日期逐个登记，不确定归属的先记下
3. **补规则**：把"可以/不可以/必须/仅限"这类判定句挑出来
4. **标口径**：凡"预计/约/截至/参考"必须连口径一起记，不能只记数

> 图片里的表格最容易漏。逐张 Read 看清表头、末行、合计行，**表头决定数字含义**（"报名人数"和"过审人数"是两个事实）。

## 四、8 种常见失真（逐条自查）

| # | 失真类型 | 错误示例 | 正确做法 |
|---|---|---|---|
| 1 | 改数字 | 原文 11779 → 写成"近 1.2 万"（可接受）但写成"1.3 万"（错） | 约数只能往**准确方向**取整，且标"约" |
| 2 | 加因果 | 原文只说"竞争比 98:1"，写成"因为缩招所以竞争激烈" | 因果若无原文支撑，改为并列陈述 |
| 3 | 把预计写确定 | 原文"预计 70 万人报名" → "70 万人报名" | 保留"预计/约"，并在文末注明口径 |
| 4 | 时间错位 | 把"报名截止"写成"笔试时间" | 每个时间必须和历史/流程节点对齐 |
| 5 | 范围扩大 | 原文"部分岗位限应届" → "都要求应届" | 保留限定词（部分/个别/除…外） |
| 6 | 张冠李戴 | 国考的数据写到省考段落 | 每个数字绑定来源，跨段不挪用 |
| 7 | 编造建议 | 原文没有的建议，写成"官方建议" | 建议只能来自素材，或明确写成"个人看法" |
| 8 | 漏关键限定 | 漏掉"仅限本地户籍""需 2 年基层经历" | 条件类事实必须整句保留语义 |

## 五、数字校验机制

`check_fidelity.py` 做三件事：

1. **覆盖检查**：所有 `level=must` 的 id，是否在文案里出现 `[[Fxx]]`
2. **数字比对**：
   - 从文案抽所有数字（含百分比、小数、日期）
   - 每个数字必须能在 `facts.json` 的 `numbers` 里找到**相同或等价**的值
   - 找不到 → 标 `SUSPECT`，人工确认是"编造"还是"合理换算"（如 11779 → 1.18 万）
3. **长度检查**：字数是否落在公式区间 ±20%

退出码：`0` 全过 / `1` 有硬失败 / `2` 仅有待确认项。

### 允许的等价换算

| 原文 | 允许写法 |
|---|---|
| 11779 | 11779 / 约 1.18 万 / 近 1.2 万 |
| 98.8:1 | 98.8:1 / 约 99:1 / 近 100 人抢 1 个 |
| 2026-07-22 | 7 月 22 日 / 7·22（同篇首次出现须写全年） |

**不允许**：把 98.8 写成 90+，把"前三天"写成"全程"。

## 六、返工策略

| 闸门结果 | 处理 |
|---|---|
| must 未覆盖 | 定位缺失的 `[[Fxx]]`，在主体对应位置补 1-2 句，不硬塞到结尾 |
| 数字 SUSPECT | 优先删掉该数字改为定性表述；确属换算则补"约"字并记入质检报告 |
| 数字冲突（文案与原文不一致） | **以原文为准**，改文案，绝不改 facts |
| 字数超上限 | 砍 should 细节和形容词，must 一条不能删 |
| 字数低于下限 | 补 should 细节或加一个"容易忽略的点"，禁止注水废话 |

## 七、特殊情形

- **区间数据**（"60-70 分"）：整体作为一个事实，不能只取一端
- **"以上/以下"**：必须连边界词一起写（"本科以上"≠"本科"）
- **多版本公告**（补充公告/更正）：以最新为准，且在 facts 的 `note` 标明"以 X 月 X 日补充公告为准"
- **无来源数字**：素材里出现但归属不明 → 不进正文，记入质检报告"未采用"
- **OCR 不确定**：数字模糊（如 8/3、0/6 难辨）→ 标 `【待确认】`，不进正文
